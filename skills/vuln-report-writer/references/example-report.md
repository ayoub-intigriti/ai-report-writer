# Example: weak vs. good report

Both describe the same (fictional) broken access control issue on `app.example.com`.

## Weak report (don't do this)

> **Title:** Critical Security Vulnerability Found in Invoice System
>
> **Description:** Insecure Direct Object Reference (IDOR) is a type of access control vulnerability that arises when an application uses user-supplied input to access objects directly. IDOR vulnerabilities were popularized in the OWASP Top 10 and remain one of the most common issues in modern web applications... *(three more paragraphs)*
>
> **Steps:** 1. Log in. 2. Go to invoices. 3. Change the ID to `<VICTIM_ID>` using this payload: `GET /api/invoice?id=1 OR 1=1`
>
> **Impact:** An attacker could download every invoice, use the data to take over accounts, perform phishing at scale and potentially compromise the entire company.
>
> **Video:** https://youtube.com/watch?v=...
>
> **Severity:** Critical

Problems: generic title; lecture instead of description; vague steps with a placeholder and an unrelated, untested payload; no requirements or raw request; speculative impact; evidence on YouTube (Code of Conduct violation); inflated severity.

**6.2 Proof of Concept / description**
````
This report was generated by Intigriti AI Report Writer for Claude.

The invoice PDF endpoint returns any invoice by numeric ID without checking it belongs to the authenticated user's organization, so a user can download other organizations' invoices by changing the ID.

Requirements
- Two accounts in different organizations: Attacker (attacker@test.example) and Victim (victim@test.example), both free-tier via /signup.

Steps
1. Log in as Victim, go to Billing > Invoices, note the newest invoice ID (48213).
2. Log in as Attacker, go to Billing > Invoices, click "Download PDF" on one of your own invoices and intercept the request.
3. Replace the ID with 48213 and send:

```http
GET /api/v2/invoices/48213/pdf HTTP/2
Host: app.example.com
Cookie: session=<Attacker's session cookie>
```

Observed result
200 OK with Victim's invoice PDF — organization name, billing address and line items (screenshot-2.png).
````

**6.3 Impact**
```
Any authenticated user can download other organizations' invoices (organization name, billing address, plan, amounts). IDs are sequential, so other invoices follow by changing the ID. Testing was limited to the two test accounts above.

Severity: Medium — read-only cross-tenant billing exposure; Confidentiality scored Low per Triage Standards §3.1.6 (https://kb.intigriti.com/en/articles/10335710-intigriti-triage-standards).
```

**6.4 Recommended solution**
```
Enforce an ownership check so an invoice is only served when it belongs to the requesting user's organization.
```
