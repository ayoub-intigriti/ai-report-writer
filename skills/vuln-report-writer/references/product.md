# Product flavor: non-web findings

Use this module together with [report-structure.md](report-structure.md) (shared skeleton) and [severity.md](severity.md) (severity). Read it when the finding is **not an HTTP web app**, for example desktop, mobile, firmware, hardware, CLI, library, or thick client. It defines only the parts that differ from web findings; everything else comes from the skeleton.

## Field 3: Endpoint / vulnerable component
- Put the **product's download URL** here. This is where Intigriti expects it for product findings. Use the link if it was shared, else `[TODO: product download URL]`.
- If there is no download (e.g. a hosted device), use the affected **component, binary or function** instead.

## Environment (required)
Add a `### Environment` block under `## Requirements` in the PoC. Fill each line; use `[TODO: ...]` for anything the researcher did not provide:
- Product name and version/build
- OS and version
- CPU architecture (e.g. x86-64, ARM64)
- Relevant runtime / dependency versions

## PoC: commands
- Put the **commands, inputs or crash output** that reproduce the finding inline, directly under the step that runs them, instead of an HTTP request.
- Include any preparation commands (e.g. `openssl`) under their step too.
- If a step needs no command, just write the action. Never write filler like "no HTTP requests are made".
