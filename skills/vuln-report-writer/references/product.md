# Product flavor — non-web findings

Use this module together with [report-structure.md](report-structure.md) (shared skeleton) and [severity.md](severity.md) (severity). Read it when the finding is **not an HTTP web app** — desktop, mobile, firmware, hardware, CLI, library, or thick client. It defines only the parts that differ from web findings; everything else comes from the skeleton.

## Field 3 — Endpoint / vulnerable component
- Put the **product's download URL** here — this is where Intigriti expects it for product findings. Use the link if it was shared, else `[TODO: product download URL]`.
- If there is no download (e.g. a hosted device), use the affected **component, binary or function** instead.

## Environment (required)
Add a `### Environment` block under `## Requirements` in the PoC. Fill each line; use `[TODO: ...]` for anything the researcher did not provide:
- Product name and version/build
- OS and version
- CPU architecture (e.g. x86-64, ARM64)
- Relevant runtime / dependency versions

## PoC — Request / Commands
- Use the **commands, inputs or crash output** that reproduce the finding, instead of an HTTP request.
- Include any preparation commands (e.g. `openssl`).
- If a subsection does not apply, **omit it silently** — never write filler like "no HTTP requests are made".
